# FAE Design Win Simulator — Web edition

TI非公式の個人学習アプリ。React + TypeScript + Vite / IndexedDB。
Lv.1の1分4択から、Lv.5のヒアリング・成立性検証まで対応する。
TIへの置換を前提とせず、採用の記載と推定された採用理由を区別する。

## 利用

公開URL: https://takuto-ando.github.io/ando_profile/fae-simulator/
管理者ページの解除後一覧からも開ける。アプリ自体は公開され、管理者パスワードでは保護されない。

- 初期値はLv.1・1問。1/3/5/10問、3段階ヒント、自己評価、苦手分野の復習に対応。
- 「全体の進捗」で回答済み/総数、未回答数、進捗率、Lv.1〜3と案件演習の内訳を確認できる。再回答は重複せず、正解率・習熟度とは区別する。現在の問題一覧が対象で、案件はLv.4〜5を通じて1件と数える。
- Lv.1〜3は21の顧客課題を3形式（技術判断・理由・短い提案）で扱う。型番を知らなくても解ける。Lv.4は要件・構成・比較、Lv.5は既存の本格演習。
- 全レベルは同じ演習ページ・共通の問題エリアで切り替える。履歴・ダッシュボード・資料・データ管理は同じページの補助パネル。補助パネルを開いても入力中の演習は保持する。
- 基本解説に加え、各選択肢の判断理由、顧客への確認事項、TIの関連候補と参考資料を表示する。具体的な型番の適合は未検証として扱う。
- 時間制限・誤答ペナルティ・自動昇級なし。自由文の技術正誤は自動断定しない。
- 公開版には基礎問題・架空案件と、ユーザー指定Excelの164型番を同梱する。取り込み操作なしでIC学習・候補選択を利用できる。Notion全体の実例は同梱しない。
- 回答と取り込んだ事例はブラウザ内へ保存する。API・アップロード・analytics・自動同期はない。
- 初回オンライン読込後はオフライン学習可能。根拠の外部リンク/PDFは同梱しない。

## 採用記載ICの学習・提案候補

指定Excelの164型番は標準教材として反映済み。ユーザー側の操作は不要。元資料A/B35型番を優先し、説明条件を満たす27型番は提案案件として保持する。型番の役割を当てる旧4択は新規出題しない。資料の関連カテゴリから技術判断問題へ進み、本格提案で164型番を候補として選択できる。元のExcelの記載と独立検証済みの事実は区別する。

別の資料への差し替えは任意。「別のIC資料に差し替える」から、同じシート構造のExcel（10MB以下）または資料JSONを選ぶ。既存のカスタム資料・Notion事例・履歴は勝手に初期化しない。差し替えた資料は端末内のみで保存し、他端末へアップロードしない。

- 全型番を検索し、役割・採用例・設計確認・元の証拠ラベルと説明確度を参照できる。
- P1はIndustrial関連A/B、P2はその他A/B、P3はC/D。A/Bでも系列推定・未同定・採用先不明は自動出題から除外する。
- 関連カテゴリのLv.1〜3と、Lv.4〜5の事例演習へ接続する。技術判断問題はその型番の採用理由や適合を当てるものではない。旧問題の履歴・回答時の解説は変更しない。
- 提案フォームの「採用記載ICから提案候補を選ぶ」で候補を選択し、選定欄へ資料記載・未確認事項・設計確認ポイント・出典を追記する。Lv.5のTI候補名にも反映するが、能力値・根拠引用・成立判定は自動入力しない。
- 出典はファイル名・SHA256・シート・行・元セルの文字列を保持。採用理由、一次根拠URL/引用/確認日は、元データにないため不明のまま。製品ページ候補は採用根拠ではなく、存在や現行性も別途照合が必要。
- IC資料JSONを別途export/importできる。学習履歴JSONには解いた問題と提案のスナップショットが残るが、未回答のIC一覧は含まれない。別端末へは資料JSONと履歴JSONの両方を移す。自動同期なし。
- ユーザーの明示指示により、このExcel由来の正規化内容（採用記載・元セルを含む）を`src/data/ic-reference.json`として公開repo・アプリに同梱する。元xlsxそのもの、Notion全体、個人の回答履歴は同梱しない。標準教材は初回取得後オフラインでも利用可能。
- 開発者が標準教材を更新する場合は`npm run import:ic -- /path/to/reference.xlsx src/data/ic-reference.json`を実行して差分を確認する。この出力先は公開される。出力先省略時は従来どおり`public/data/ic-reference.json`へ変換するだけで、標準教材は更新しない。

追加テスト: `python3 tests/browser_ic.py --url http://127.0.0.1:4178/ --output /tmp/fae-ic-test`（Playwrightが必要、架空Excelを自動生成）。実データ試験は`--workbook /path/to/reference.xlsx --part PART --count 164`を指定する。出力には資料内容が含まれるため公開しない。

## 履歴を引き継ぐ

旧型番暗記問題は履歴表示・JSON互換のために保持するが、通常出題・復習プールへ戻さない。旧履歴の「復習」は同じテーマ・レベルの技術判断問題へつなぐ。新問題には別IDを付けるため、旧回答は消えないが新カタログの回答済みには数えない。

以前のローカル版の「データ管理」で履歴JSONをエクスポートする。
Web版の「データ管理」からインポートすると、新旧の回答を同一IDは既存優先で統合する。
ローカル版とWeb版、異なる端末・ブラウザは保存領域が異なるため自動では移らない。
ブラウザのデータ削除前にJSONでバックアップする。機密・顧客の非公開資料は取り込まない。

## 開発・ビルド

### 統合したローカルTI教材

`ti_block_diagrams/quizzes/`のBlock Diagram、Digital Seminar、Analog Seminarを再構成して利用。元の固定問題は57・115・103件で、合冊Seminarの218件はDigital+Analogと重複するため追加しない。Product Quizの122カテゴリも含め、元の暗記問題や不適切な誤答をそのまま一括投入せず、Industrial FAE向けの21課題を選び直した。

優先順は処理構成・制御 → 通信 → 産業用電源 → センシング/I/O → 絶縁/保護 → システム → 比較/Design Win。Lv.1〜3の63形式は21テーマの段階学習であり、独立した63案件ではない。初期の40件の本格案件と合わせて103問として回答進捗を表示する。端末内Notion取り込み・資料差替えで分母は変わる。

各設問に元教材のファイル・問題IDまたは箇所を保持する。元教材の外部未検証情報は未検証のまま扱い、製品仕様・採用理由の証拠へ昇格させない。公開版へ元HTML/PDF・Notion全体を追加公開しない。根拠リンクは参照用で、自動取得しない。

統合UIの実走確認は`tests/browser_levels.py`、`tests/browser_public.py`、`tests/browser_workflow.py`、`tests/browser_ic.py --bundled --part AM2434 --count 164`で行う。`--url`に起動先を指定する。`tests/browser_smoke.py`はローカルNotionデータ（351案件）を前提とするため公開版では実行しない。

Node.js 22 / npm。ここで実行する。

```bash
npm ci
npm run check
npm test
npm run dev
npm run build:public
```

公開出力は `dist-public/`。既定baseは `/ando_profile/fae-simulator/`。
別パスの場合は `FAE_BASE_PATH` 環境変数に末尾 `/` 付きのパスを指定する。
public buildは `publicDir` を無効にし、出力ファイルもHTML・JS・CSS・SWに限定して検査する。
`public/data/`、`data/notion-export/`、履歴JSON、認証情報をGitへ追加しない。
非公開Notionデータを使うローカルテスト1件は、このリポジトリではskipする。その他は架空fixtureと、明示公開したIC標準教材を検証する。

GitHub Actionsはこのソースを検査・ビルドし、Jekyll出力へ合流させる。
ソースディレクトリ自体はJekyllの出力対象外だが、GitHubリポジトリでは公開される。
Service Workerはアプリのサブパスだけを対象とし、プロフィールやadminのページはキャッシュしない。
