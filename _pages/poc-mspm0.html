マイコン・イベント駆動ファームウェア

個人PoC / 入力イベントのソース例あり / 測定記録を整理中

GPIO割込み、タイマによるデバウンス、ADC連続変換、UART出力、__WFIを組み合わせたMSPM0のファームウェアの動作検証。

課題と目的

MSPM0の周辺機能を個別に動かすだけでなく、入力イベントの検知とADCのサンプリングを共存させる実装に取り組みました。GPIO、タイマ、ADC、UARTを組み合わせ、MCUが入力を受けて処理する一連の流れを確認することが目的です。

24V DI PoCでは回路からMCUまでの接続を扱い、このページではファームウェアと周辺機能の制御を中心にまとめます。割込み・デバウンスの経験には重複があり、別々の製品開発実績として数えるものではありません。

実装構成

PA25 / 立下りエッジ→GPIO割込み→TimerG / デバウンス→イベントカウント / UART
PA24 / ADC入力→ADC12 / 連続変換＋GPIO割込みとの共存

実際に取り組んだこと

GPIO割込みとタイマによるデバウンス

PA25の立下りエッジをGPIO割込みで検知し、TimerGを使ったデバウンス処理を実装しました。イベント数をUARTで表示し、入力イベントをファームウェアで受け取る動作を確認しました。

TimerGの設定値、判定までの時間、割込み中に次の入力が入った場合の処理は、ソースコードと対応付けて追記します。

ADC12の連続サンプリング

PA24を使ったADC12の連続変換を動かし、GPIO割込みとの共存も試しました。タイマ、ADC、IRQを組み合わせた周辺機能制御の経験として整理します。

ADCのクロック、サンプリング条件、結果の取得方法、タイマとADCの具体的な接続関係は未整理です。タイマによるADCトリガやDMA利用は、この記録からは確認できません。

__WFIによるイベント待機

__WFIを使うイベント駆動の実装に取り組みました。待機からイベント処理へ移るファームウェアの構成を扱った経験として記載し、消費電流の削減量や応答時間は実測してから評価します。

入力イベントをUARTへ送る保存コード

保存していたMSPM0C1104向けプロジェクトから、GPIO入力、LED、UART、イベント待機をつなぐソース例を整理しました。SysConfigの記録はMSPM0 SDK 2.11.00.07、SysConfig 1.26.2、VSSOP-20（DGS20）です。

PA25 / 両エッジ割込み→入力がHighならカウント→LEDと通知フラグ→UART出力 / __WFI

入力イベントのCソースを見る

割込みで入力を読み、Highの場合にイベント数を増やしてLEDを点灯します。メインループは通知フラグを確認し、UARTへイベント数を送ってから待機します。保存設定のUARTは115200 bps、TXはPA27、RXはPA26です。

この添付コードは入力イベントの例です。上で紹介したTimerGのデバウンスやADC結果の処理をすべて含む版ではありません。SysConfigの生成ヘッダ・設定ファイルも別に必要で、このCファイル単体ではビルドできません。保存コードの確認と、現在の環境でのビルド・実機再試験は区別しています。

このPoCで扱った範囲

  • GPIOの立下りエッジ割込みとTimerGによるデバウンス
  • UARTを使ったイベントカウントの可視化
  • ADC12の連続変換とGPIO割込みの共存
  • __WFIを含むイベント駆動ファームウェア

経験の紹介文

個人PoCとして、MSPM0のPA25 GPIO割込み、TimerGデバウンス、UARTイベントカウント、__WFIを実装しました。PA24のADC12連続変換とGPIO割込みの共存にも取り組んでいます。

個人PoCの経験と、添付した入力イベントの保存コードを紹介しています。測定ログ・波形は未添付で、サンプリング速度、ADC精度、消費電流、割込み応答時間の定量評価は未整理です。
